# 04. M4 — Поиск

> Этап: M4 · Оценка: 1.5 дня · Зависит от: M2 (библиотека), M3 (транскрипция) · Разблокирует: M6 (поиск по тегам), M7 (поиск по меткам), M8
> Владелец: writer-search

## 1. Цель и границы

M4 превращает накопленный индекс (`videos` + `segments`) в сквозной полнотекстовый поиск: миграция FTS5, безопасный разбор пользовательского запроса, единый эндпоинт `GET /api/search`, сниппеты с подсветкой и UI-контур «поле в тулбаре → результаты → переход на таймкод». Этап закрывает критерий `../TARGET.md` §7 п.4 и создаёт точку расширения для поиска по пользовательским меткам (`kind:"annotation"`), которую наполняет M7.

**Что делает этап:**
- миграция `004_segments_fts.sql`: FTS5 external content + триггеры INSERT/UPDATE/DELETE + backfill;
- модуль `utils/fts_query.py`: разбор запроса, разрешены только `AND`/`OR`/`NOT` и фразы в кавычках, произвольный синтаксис FTS5 запрещён;
- префиксы `tag:` и `file:`; `VIDEO_ID`, `tag_ids`, `colors`, `limit`, `offset`;
- `GET /api/search` по контракту `./00-conventions.md` §4: `scope=all|files|segments|annotations`, элементы `kind: file|segment|annotation`;
- сниппеты через `snippet()` с `<mark>`, ранжирование `bm25`, пагинация;
- UI: поле поиска в тулбаре, debounce 300 мс, Enter/Esc, строка «Найдено N…», панель результатов, подсветка, клик → открыть видео на `start_ms`, пустой результат, контекст папки/тега.

**Чего этап не делает (границы):**
- не реализует поиск по меткам: `annotations_fts` и провайдер `kind:"annotation"` — задача M7; M4 обязан вернуть валидный пустой ответ для `scope=annotations`;
- не создаёт и не редактирует теги (`M6`) — только читает `video_tags`/`segment_tags`/`tag` при фильтре `tag:`;
- не меняет `GET /api/videos?q=` (M2) и не дублирует фильтрацию списка файлов;
- не делает морфологический/семантический поиск и `sqlite-vec` (см. §9, риск R-04.1);
- не делает плеер, таймлайн и панель таймингов (M5) — только контракт «результат → открыть видео на `start_ms`»;
- не вводит отдельный эндпоинт «поиск по папке»: контекст папки/тега передаётся параметрами фильтра.

**Готово, когда** (`../TARGET.md` §6, M4): ввод слова из середины урока возвращает файл и таймкоды; клик по сниппету открывает видео на нужной секунде.

## 3. Решения

**D1. Реестр провайдеров вместо «if scope».** `search_service` содержит `SEARCH_PROVIDERS: dict[str, Provider]`; каждый провайдер возвращает `(items, total)` и не знает о других. M4 регистрирует `file` и `segment`, M7 добавляет `annotation` одной строкой регистрации — роутер, pydantic-схемы и фронтенд при этом не меняются. Это прямое исполнение `./00-conventions.md` §2 A9 и §12.

**D2. Санитайзер — единственная точка контакта с FTS5.** `utils/fts_query.py` разбирает вход в собственное AST и только затем сериализует в FTS5. Всё, что не распознано как оператор/фраза/слово, становится литеральным токеном, а не SQL-фрагментом. Строка MATCH всегда передаётся параметром (`:q`), без f-string и без конкатенации.

**D3. Грамматика запроса — плоская.** `term ((AND|OR|NOT) term)*`, где `term` — слово, фраза в двойных кавычках или префикс `tag:`/`file:`. Операторы распознаются только в верхнем регистре; `NOT` — только бинарный (в начале и в конце строки отбрасывается); непарная кавычка автозакрывается, потому что пользователь ещё печатает. Пустые скобки, `NEAR`, `col:`, `^`, `*`, `{}`, `-` и прочий синтаксис FTS5 в AST не попадают — они становятся литералами или отбрасываются.

**D4. Имена файлов ищутся без FTS.** Видео-файлов в библиотеке тысячи, а не миллионы; `LIKE` по `lower(title)`/`lower(path)` с экранированием `%`/`_` дешевле отдельной FTS-таблицы и не требует изменения контракта `./00-conventions.md` §5 (таблицы `files_fts` там нет). Скоринг файлов — эвристика: совпадение basename = 2.0, совпадение с начала слова = 1.5, подстрока = 1.0.

**D5. Единая шкала score.** `bm25()` в SQLite возвращает отрицательные числа (меньше — релевантнее), поэтому `score = round(-bm25(...), 3)`; для файлов score положительный по D4. Слияние — сортировка по `score DESC`, затем `kind` (segment → annotation → file), затем `video_id`, `start_ms`. Детерминированный tie-break обязателен: пагинация не должна «терять» элементы между страницами.

**D6. Веса bm25 фиксированы и централизованы.** В M4: `bm25(segments_fts, 1.0)`. В M7: `bm25(annotations_fts, 2.0, 1.0)` (label 2.0, note 1.0) — ровно как требует постановка. Веса хранятся в константах `search_service.py`, а не размазаны по SQL, чтобы M7 унаследовал шкалу.

**D7. Сниппет собирается в два шага.** `snippet(segments_fts, 0, :m1, :m2, '…', 12)` вызывается с плейсхолдерами `\x01`/`\x02`; затем весь фрагмент проходит `html.escape(quote=False)`, и только после этого плейсхолдеры заменяются на `<mark>`/`</mark>`. В БД и в ответе не появляется неэкранированный HTML, в том числе если в транскрипции встретился `<img onerror=…>`.

**D8. Пустой эффективный запрос — режим фильтра.** Если после снятия префиксов слов не осталось (например, `tag:Математика`), MATCH не выполняется: фильтр применяется напрямую к `video_tags`/`segment_tags`. Это нужно M6 для «клик по тегу → список файлов» и M7 для фильтра по цвету.

**D9. `scope=annotations` в M4 — валидный пустой ответ.** 200, `items: []`, `total: 0`. Не 501 и не 400: UI и тесты M4 уже сейчас видят стабильный контракт, M7 меняет только содержимое. Ошибка была бы ломкой контракта через 2 этапа.

**D10. Дебаунс и защита от гонок — на клиенте.** 300 мс; Enter — принудительный запрос немедленно; Esc — очистка и возврат к контексту; каждый запрос получает `seq`, ответ применяется только если `seq === current`; предыдущий `fetch` отменяется `AbortController`. Это дешевле серверных отмен и устраняет «мигающие» результаты при быстром вводе.

**D11. `tag:` — разбор в M4, комбинирование расширяет M6.** M4 распознаёт `tag:<имя>` и `tag:"<путь>"` в `fts_query.py` и передаёт сервису структурный список `tags`; базовая семантика M4 — точное листовое имя (NOCASE), несколько термов через OR, без поддерева. M6 (`./06-tags-m6.md` §3 п.7, §4) расширяет контракт: `tag_mode=any|all` (по умолчанию `any`, `include_children=1` — `00` §4.1 п.2), полный путь с `/`; меняется только композиция фильтра в сервисе и параметры запроса, форма ответа `/search` не меняется. Несуществующее имя тега даёт пустой результат, а не ошибку.

**D12. `file:` — подстрока по имени, не по пути.** `file:lesson` находит `lesson-01.mp4`; путь в сниппет файла не попадает (в UI он показывается отдельной строкой, чтобы не дублировать длинные пути). Совместно с обычными словами `file:` сужает выборку: FTS-часть ищется по сегментам, файловая — по именам, затем пересечение по `video_id`.

**D13. Контекст папки/тега ограничивает поиск, но не блокирует его.** Если слева выбрана папка (M2) или тег (M6), непустой запрос выполняется с фильтром контекста; в панели результатов виден бейдж «В папке …»/«С тегом …» и кнопка «Искать везде», снимающая ограничение до следующего изменения контекста. Пустой запрос контекст не трогает — показывается текущий список файлов (`../TARGET.md` §3.3).

## 4. Изменения контрактов

**Реализуется без изменения контракта** (уже зафиксировано в `./00-conventions.md`):

| Артефакт | Что именно | Источник |
|---|---|---|
| Миграция `004_segments_fts.sql` | `segments_fts` external content + 3 триггера + backfill | 00 §5 (004) |
| `GET /api/search` | параметры `q`, `scope`, `video_id`, `tag_ids`, `colors`, `limit`, `offset` | 00 §4 |
| Форма ответа | `{query:{raw,fts,scope,prefixes}, total, items[]}`; `kind: file\|segment\|annotation` | 00 §4 |
| Сниппеты | `snippet_html` с `<mark>…</mark>` | 00 §2 A8 |
| Семантика `q` | FTS5, `AND/OR/NOT`, фразы, `tag:`, `file:`, запрет произвольного синтаксиса | 00 §4 |

Фрагмент миграции (триггеры, иллюстративно):

```sql
CREATE TRIGGER segments_ai AFTER INSERT ON segments BEGIN
  INSERT INTO segments_fts(rowid, text) VALUES (new.id, new.text);
END;
CREATE TRIGGER segments_ad AFTER DELETE ON segments BEGIN
  INSERT INTO segments_fts(segments_fts, rowid, text) VALUES ('delete', old.id, old.text);
END;
CREATE TRIGGER segments_au AFTER UPDATE ON segments BEGIN
  INSERT INTO segments_fts(segments_fts, rowid, text) VALUES ('delete', old.id, old.text);
  INSERT INTO segments_fts(rowid, text) VALUES (new.id, new.text);
END;
INSERT INTO segments_fts(segments_fts) VALUES ('rebuild');
```

**Ратифицировано Lead'ом (`./00-conventions.md` §4.1 п.3):**

| Артефакт | Решение | Обоснование |
|---|---|---|
| `query.took_ms` (int) | принято: аддитивное поле в ответе | бюджет `p95 < 150 мс` и диагностика |
| `query.prefixes` форма | принято: `{"tags": [...], "file": "lesson"\|null}` | тип зафиксирован |
| `limit` по умолчанию 20, максимум 100 | принято | размер панели результатов |
| Коды ошибок `invalid_scope`, `invalid_limit`, `query_too_long` | принято: 422 + `{detail, code}` | формат ошибок 00 §4 |
| `tag_mode`, `include_children` | принято: `tag_mode=any` по умолчанию, `include_children=1`; окончательная семантика — M6 (`00` §4.1 п.2) | M4 валидирует параметры, применяет базовую OR-семантику |

**Производные решения, не требующие правки контракта:** `scope=all` в M4 = `files + segments` (annotations подключит M7); `scope=files` не ищет по сегментам; `scope=segments` не возвращает `kind:"file"`; `video_id` сужает любой scope; `tag_ids` (CSV) — фильтр по id тегов, независимый от `tag:` (оба могут действовать одновременно, пересечение).

**Ратифицировано Lead'ом (`00` §4.1):** вопросы 1, 2, 4, 5 закрыты — семантика `tag:`/`tag_mode` фиксируется M6 с дефолтом `any`, `colors` применяется только к меткам (M7), `took_ms` принят, IPC не добавляется. Пункт 3 (контекст поиска) остаётся реализационным решением M4/M6.
1. **Семантика `tag:` между M4 и M6.** M6 принял `tag_mode=any|all` (по умолчанию all) и `include_children`; M4 реализует базовую OR-семантику как временную. Нужно подтвердить, что смена поведения `tag:` в M6 допустима, а M4 не обязан реализовывать AND заранее; иначе — параметр вводится уже в M4 (оценка +0.1 дня).
2. **`colors` в M4** — параметр принимается и валидируется, но применяется только к меткам (M7). Нужда ли в нём для сегментов/файлов — не определена.
3. **Контекст поиска (D13)** — «искать в текущей папке/теге» расширяет TARGET буквально; возможно, Lead предпочтёт глобальный поиск с фильтрами-чипами.
4. **`query.took_ms`** — если Lead против расширения ответа, поле уходит в debug-лог и в тестах проверяется по времени выполнения запроса.
5. **Интерфейс `window.vl`** — M4 не добавляет IPC-каналов; если понадобится «открыть видео из результата» без смены маршрута, это решается на уровне стора, не IPC.
6. **Селектор области в тулбаре** — M7 (`./07-annotations-m7.md` §6) добавляет «Везде / Файлы / Сегменты / Метки». M4 хранит `scope` в `searchStore` и прокидывает в API, но селектор не показывает; подтвердить, что это разделение устраивает M7.

## 6. UI/UX-спецификация

```
Toolbar:  [＋ В анализ] [－ Из анализа]   [🔍 Поиск: __________________ ×]
                                                            │ 300 мс
                           ┌─────────────────────────────────┴──────────────┐
                           │ Найдено 7 результатов по запросу "производная" │
                           │ lesson-01.mp4 · 12:34                          │
                           │   [07:12] …вторая <mark>производная</mark>…    │
                           │   [19:40] …правило <mark>производной</mark>…   │
                           └────────────────────────────────────────────────┘
```

**Поведение поля поиска:**

| Событие | Поведение |
|---|---|
| ввод | debounce 300 мс, запрос с текущим контекстом; при длине < 1 непробельного символа поиск не выполняется |
| `Enter` | немедленный запрос, фокус остаётся в поле |
| `Esc` | очистка поля, закрытие панели результатов, возврат к списку файлов контекста |
| `Ctrl+F` | фокус в поле (глобальный хоткей M1/M9, M4 подключает обработчик) |
| очистка `×` | то же, что `Esc`, без смены контекста |
| ошибка сети | строка ошибки над панелью + кнопка «Повторить», старые результаты сохраняются |

**Панель результатов:**
- открывается при непустом `debouncedQuery` или ненулевом результате; список файлов под ней остаётся видимым (панель — overlay справа от списка, ширина 360–480 px, не перекрывает тулбар);
- группировка по видео: заголовок с названием файла и общим числом совпадений, под ним строки сегментов в хронологическом порядке;
- строка сегмента: `[MM:SS]` (через `formatTimecode`), сниппет с `<mark>`, hover — фон `--vl-hover`, активная строка — `--vl-accent-soft`;
- контрастность подсветки `<mark>` ≥ 4.5:1 в light/dark (проверка контраста — §7);
- результат `kind:"file"` — строка с иконкой файла, путём (обрезан `text-overflow`) и бейджем «файл»;
- при `total > 20` — кнопка «Показать ещё» (offset-пагинация), без виртуализации: 20–100 DOM-узлов дешевле виртуализации по сложности;
- пусто: «Ничего не найдено по запросу "…"» + подсказка «Попробуйте одно слово, фразу в кавычках или tag:имя»;
- клавиатура: ↑/↓ по строкам, Enter — открыть, Esc — закрыть панель; `aria-live="polite"` на счётчике.

**Контекст:** при выбранной папке/теге placeholder — «Поиск в папке «…»» / «Поиск по тегу «…»»; в шапке результатов — бейдж контекста и кнопка «Искать везде». При пустом запросе панель не показывается, список файлов отражает контекст (M2/M6). Селектор области «Везде / Файлы / Сегменты / Метки» добавляет M7 (`./07-annotations-m7.md` §6); M4 хранит `scope` в `searchStore` и прокидывает его в API, но контрол не рисует.

**Доступность:** поле связано с панелью через `aria-controls`; счётчик — `aria-live="polite"`; панель закрывается `Esc`, не ловит фокус при открытии (не модалка); все кликабельные строки — `role="option"` в `role="listbox"` с `aria-activedescendant`.
