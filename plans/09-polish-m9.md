# 09. M9 — Полировка

> Этап: M9 · Оценка: 1–2 дня · Зависит от: M1–M8 · Разблокирует: M10
> Владелец: writer-release

## 1. Цель и границы

**Цель.** Довести приложение до состояния, в котором выполняются критерии `../TARGET.md` §7 (кроме п.1 — чистая ВМ, его ведут M8/M10): горячие клавиши и окно «О клавишах», окно настроек, toast-уведомления и человекочитаемые ошибки, тёмная тема, i18n (`i18n/ru.json`), логи с ротацией, доступность (контраст ≥ 4.5:1, клавиатурная навигация), восстановление UI-состояния.

**Требование пользователя** (`./00-conventions.md` §12): `Ctrl+M` обязателен для ручных меток и должен быть описан в окне «О клавишах» вместе с горячими клавишами поиска (включая операторы `tag:`/`file:`); контролы меток (цвет, теги, заметка, сохранение, удаление) обязаны быть полностью доступны с клавиатуры.

**Границы (этап не делает):**

1. Новые функции меток, тегов и поиска — объём M4–M7; M9 только связывает их с клавиатурой, настройками и текстами.
2. Английская локаль и переключатель языка интерфейса — вне объёма (A15); готовится только структура ключей.
3. Автообновление, телеметрия, системные уведомления ОС, трей — вне объёма TARGET.md.
4. Undo/redo меток и тегов — M7 (при наличии) и далее; M9 не вводит историю действий.
5. Изменения схемы БД: M9 добавляет только ключи в `settings` (A12), миграции не создаются.
6. Упаковка и чистая ВМ — M8/M10; M9 лишь финально прогоняет критерии §7 п.2–10 и фиксирует результаты в `docs/acceptance.md`.

## 3. Решения

1. **Единый реестр клавиш.** `hooks/useHotkeys.ts` уже используется M4 (`Ctrl+F`), M5 (`Space`, стрелки) и M7 (`Ctrl+M`, `Delete`, `Esc`, `Shift+I`/`Shift+O`, `Ctrl+Z`), реестр M7 держит в `lib/constants.ts`. M9 консолидирует реестр в `frontend/src/lib/hotkeys.ts` — декларативный список `{id, code, ctrl?, alt?, shift?, scope, labelKey}`, а `hooks/useHotkeys.ts` вешает один `keydown`-обработчик на `window` и маршрутизирует по scope; поведение существующих клавиш не меняется. Сравнение по `event.code` (`KeyF`, `KeyO`, `KeyM`, `Space`, `F1`), чтобы сочетания работали в русской раскладке; `Esc`/`Enter` — по `event.key`. Глобальные акселераторы Electron-меню не дублируют эти клавиши, иначе срабатывание двойное.
2. **Guard ввода.** Базовая проверка `isEditable` уже есть в M4/M5/M7; M9 расширяет её до правила: если фокус в `input`/`textarea`/`select`/`contenteditable`, обрабатываются только «безусловно глобальные» клавиши (`Ctrl+F`, `Ctrl+O`, `Ctrl+M`, `F1`); `Space`, `Delete`, стрелки и `Ctrl+Enter` — только в своих scope (плеер, тайминги, список меток, дерево). `Space` на сфокусированной кнопке/ссылке не перехватывается, чтобы не ломать нативную активацию.
3. **`Ctrl+M`** (реализация создания — M7, `./07-annotations-m7.md` D5): если в панели таймингов выделен диапазон строк — по нему, иначе — на позиции плеера (`start = playhead`, `end = playhead + 5 c`). M9 добавляет к диалогу `Ctrl+Enter` («Сохранить», принято в `00` §4.1), `Esc` (отмена) и возврат фокуса на созданную метку.
4. **Окно «О клавишах»** (`F1`, пункт меню «Справка → О клавишах») строится из реестра: группы «Поиск и файлы», «Плеер и тайминги», «Метки», «Интерфейс»; в шапке — подсказка по операторам `tag:` и `file:`; обязательные строки: `Ctrl+M` «метка на позиции плеера или выделенном диапазоне», `Ctrl+F` «фокус в поле поиска», `Ctrl+O` «добавить файлы в анализ». Реализация — `role="dialog"`, `aria-modal`, ловушка фокуса, `Esc` и `F1` закрывают, фокус возвращается на инициатора.
5. **Настройки** — `SettingsDialog` с разделами: «Библиотека» (отслеживаемые папки, «Переиндексировать всё»), «Распознавание» (модель, язык), «Интерфейс» (тема, режим мультивыбора тегов, сброс UI-состояния), «Данные» (пути данных/логов, размер кэша, «Очистить кэш моделей»), «О программе» (версии). Каждое изменение — один `PATCH /api/settings`; оптимистичное применение с откатом при ошибке; синхронизация через SSE `settings.changed`.
6. **Модели.** Офлайн-сборка содержит только `small` (следствие M8, вопрос 4.7-1): `GET /api/models` перечисляет каталоги в `${VL_RESOURCES_DIR}/models`, UI показывает отсутствующие пункты (`tiny/base/medium`) неактивными с подсказкой «не входит в офлайн-сборку». Значение `whisper_model` = `small`.
7. **Переиндексация** выполняется клиентским батчем через существующий `POST /api/videos/{id}/reprocess` (без нового bulk-эндпоинта): подтверждение с числом файлов, предупреждение, что сегменты и их теги будут пересозданы, а метки и теги файлов сохранятся; прогресс — через SSE `queue.state`/`video.status`.
8. **Тема**: токены `--vl-*` в `tokens.css` (`:root` — светлая, `[data-theme="dark"]` — тёмная); атрибут на `<html>`; при `system` — `matchMedia('(prefers-color-scheme: dark)')` с подпиской на изменение (IPC не нужен); анти-FOUC — синхронный inline-скрипт в `index.html`, читающий `localStorage.vl.theme` до первой отрисовки. Все цвета компонентов — только через токены; проверка контраста — `scripts/check-contrast.mjs` (WCAG 2.1: ≥ 4.5:1 для текста, ≥ 3:1 для крупного текста и границ контролов), падает в CI при нарушении.
9. **i18n**: плоские ключи `<область>.<компонент>.<ключ>` в `frontend/src/lib/i18n/ru.json`, доступ `t('ключ', {параметры})`; множественные формы — через `Intl.PluralRules('ru')` (`one/few/many`); коды ошибок бэкенда отображаются как `errors.<code>` с фолбэком на `detail`. Скрипт `scripts/check-i18n.mjs` ищет кириллические литералы в JSX и падает, если они не в allowlist (тесты, `docs/`).
10. **Ошибки и toast.** `lib/errors.ts` — карта `code → ключ i18n + действие`; глобальные обработчики `window.vl.onBackendStatus`, `unhandledrejection`, `error`, React `ErrorBoundary`; toast-стор с дедупликацией и `aria-live`; для фатальных ошибок — диалог вместо toast.
11. **Логи**: уровень через `log.level` (`INFO`/`DEBUG`/`WARNING`), рендерер пишет через `window.vl.log`, кнопка «Открыть папку логов» (`revealInExplorer(getAppInfo().logsDir)`); ротация проверяется тестом (10 МБ × 5).
12. **Восстановление состояния**: только UI-состояние — в `localStorage` с префиксом `vl.` и обёрткой `{v:1, value}`; данные (очередь, статусы, теги, метки) — из БД при старте (A12). Битый/устаревший JSON — дефолты + запись WARNING в лог, без падения.

### 4.4. Контракт i18n и темы

- `frontend/src/lib/i18n/ru.json` — единственный источник строк UI; ключи `<область>.<компонент>.<ключ>`; `t(key, params)` с подстановкой `{param}`; `plural(n, {one,few,many})`.

2. `GET /api/models` и `POST /api/maintenance/clear-model-cache` — **принято**, внесены в `00` §4.
3. `Ctrl+Enter` (сохранить метку) — **принято** как дополнение к §3.7 спеки.
4. `Delete` для метки — **принято** (упомянут в §3.5 спеки), включается в окно «О клавишах».
5. Токены `--vl-*` — состав определяется M9, префикс закреплён в `00` §8; смена токенов — внутреннее изменение.
6. `vitest-axe` — только devDependency, контракт не затрагивает.

### 4.7. Решения по открытым вопросам (ратифицировано Lead'ом)

1. **Модели:** в пакете только `small` (A11); `tiny/base/medium` показываются неактивными с пояснением; `whisper_model_path` не вводится.
2. **«Очистить кэш моделей»:** чистим `$VL_DATA_DIR/cache/models`, показываем объём; в офлайн-сборке каталог пуст — кнопка disabled с tooltip «кэш пуст».
3. **«Переиндексировать всё»:** метки и теги файлов сохраняются; пересоздаются сегменты и их теги; подтверждение предупреждает, что таймкоды могут сместиться при смене модели/языка.
4. **`Ctrl+1..9`:** реализуется в M5, иначе пункт в окне «О клавишах» не показывается.
5. **Тема `system`:** `matchMedia` в рендерере достаточно; IPC `nativeTheme` не добавляется.
6. **`log.level=DEBUG`:** доступен в настройках с предупреждением о размере логов и приватности; по умолчанию `INFO`.
7. **Финальный прогон §7:** M9 фиксирует п.2–10 в `docs/acceptance.md`; п.1 — M8/M10 на чистой VM.
