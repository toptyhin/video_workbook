# 06. M6 — Теги

> Этап: M6 · Оценка: 2–3 дня · Зависит от: M2, M4, M5 · Разблокирует: M7, M9
> Владелец: writer-release

## 1. Цель и границы

**Цель.** Дать пользователю полноценный домен тегов: иерархию через `parent_id` (UI — до 5 уровней), CRUD с безопасным перемещением, назначение тегов файлам, сегментам транскрипции и меткам, счётчики по поддереву, фильтрацию списка файлов, поиск `tag:` через единый `/api/search`, экспорт/импорт JSON. Результат этапа — критерий `../TARGET.md` §7 п.6: создана иерархия «Учёба / Математика / Производные», назначена на 2 файла, фильтр по «Математика» показывает оба файла.

**Границы (этап не делает):**

1. CRUD пользовательских меток, drag границ на таймлайне, FTS и UI поиска по `label`/`note` меток — M7 (`./07-annotations-m7.md`). M6 добавляет только сервис назначения тегов меткам и поле `tag_ids` в контракт метки.
2. Окно настроек — M9; M6 добавляет лишь ключ `tags.multi_select_mode` в `settings` и компактный переключатель в шапке таба «Теги».
3. Горячие клавиши уровня приложения — M9; в M6 допустимы только клавиши внутри дерева тегов (стрелки, F2, Delete).
4. Парсер пользовательских запросов, сниппеты и UI результатов поиска — M4 (`./04-search-m4.md`); M6 расширяет `tag:`-ветку и параметры фильтра, не меняя форму ответа `/api/search`.
5. Ручная drag-сортировка тегов, иконки/картинки тегов, XMP/digiKam-интероп, назначение тегов папкам, undo, теги с ограничением по типу контента — вне объёма M6.

## 3. Решения

1. **Глубина.** БД не ограничивает глубину структурно, но API и UI применяют `MAX_TAG_DEPTH = 5` (`backend/app/utils/tags.py`), значение дублируется настройкой `tags.max_depth` для будущего изменения. Обоснование: спека ограничивает UI пятью уровнями, а расхождение БД/UI привело бы к тегам, невидимым в дереве. Проверка выполняется на create и на move (с учётом глубины всего поддерева).
2. **Уникальность имён.** `UNIQUE(parent_id, name)` из `../TARGET.md` §4 не работает для корневых тегов (SQLite допускает несколько `NULL`), поэтому миграция 005 добавляет `UNIQUE INDEX ux_tags_parent_name ON tags(COALESCE(parent_id, 0), name COLLATE NOCASE)`. Сравнение регистронезависимое: «Математика» и «математика» — конфликт (`409 tag_name_conflict`). Имя нормализуется (trim, NFC, сжатие пробелов) и не может содержать `/` и `\` — разделитель пути в UI, экспорте и `tag:`.
3. **Перемещение** выполняется через `PATCH /api/tags/{id}` с полем `parent_id` (`null` — в корень) в одной транзакции: проверка, что новый родитель не является потомком узла (`400 tag_cycle`), и что глубина поддерева не превышает лимит (`400 tag_depth_exceeded`). Отдельного эндпоинта `move` не вводим.
4. **Удаление** — по схеме спеки (`tags.parent_id ON DELETE CASCADE`): удаляется всё поддерево и связи в `video_tags`/`segment_tags`/`annotation_tags`. UI показывает подтверждение со счётчиками («будет удалено N тегов, M назначений»). Режим «переподвесить детей к родителю» в M6 не реализуется (вопрос 4.4-2).
5. **Счётчики** считаются на сервере одним проходом: плоский список тегов + три рекурсивных CTE, по одному на сущность, с `COUNT(DISTINCT …)` по поддереву. Результат кэшируется в памяти процесса под монотонной ревизией `tags_rev`, которая инкрементируется при любой мутации тегов; клиент получает SSE `tags.changed` и перезапрашивает дерево. Таблица-кэш в БД не вводится, чтобы не расширять модель данных.
6. **Мультивыбор:** `Ctrl+клик` накапливает набор, `Shift+клик` выделяет диапазон видимых узлов. Семантика задаётся `tag_mode=any|all` (объединение/пересечение). Для `GET /api/videos` (клик по тегам в панели) значение по умолчанию берётся из `tags.multi_select_mode`: `union` (по умолчанию, `TARGET.md` §2.2 — «объединение») → `any`, `intersection` → `all`. Для `/api/search` по умолчанию `tag_mode=any` (объединение; `00` §4.1 п.2), как и для `/api/videos`; `all` — только явным параметром. Дочерние теги включаются всегда, кроме явного `include_children=false`.
7. **`tag:` в поиске:** терм `tag:<имя>` либо `tag:"<Путь/Ребёнок>"`; совпадение по листовому имени (NOCASE) или по полному пути; композиция нескольких термов — по `tag_mode` (по умолчанию `any`), поддерево включается (`include_children=true`). Область действия определяется `scope` (A9): `files` — теги видео, `segments` — собственные теги сегмента, `annotations` — теги метки (включается в M7). Совместимость с M4: M4 распознаёт и структурирует термы, не меняя форму ответа `/search`; M6 добавляет только композицию и параметры запроса.
8. **Экспорт/импорт** — JSON `version:1`, теги адресуются путём (`Учёба/Математика`), связи файлов — `{path, sha256}`. Импорт `mode=merge` идемпотентен: существующие теги/связи не дублируются, повторный импорт даёт нулевые изменения; `dry_run=true` возвращает отчёт без записи. Связи сегментов не экспортируются (id сегментов нестабильны при переобработке). Всё — в одной транзакции.
9. **Теги сегментов:** эндпоинты `POST/DELETE /api/segments/{id}/tags/...` (внесены в контракт `00` §4, ратифицировано); выдача `GET /api/videos/{id}/segments` расширяется полем `tag_ids` у каждого сегмента. Для меток M6 предоставляет `tags_service.set_annotation_tags()` и валидацию `tag_ids`, HTTP-эндпоинтов не добавляет — их контракт принадлежит M7.
10. **Совместимость до M7:** таблица `annotation_tags` создаётся миграцией 006 (M7), поэтому счётчик меток и `scope=annotations` в M6 обёрнуты проверкой наличия таблицы в `sqlite_master` и возвращают `0`/пусто; guard снимает M7 (`./07-annotations-m7.md` T-07.1/T-07.2).
11. **UI-стек:** новых зависимостей нет — HTML5 drag-and-drop, zustand-стор `tagsStore`, компоненты из `components/sidebar` и `components/ui`. Дерево тегов рендерится целиком (виртуализация не нужна при лимите глубины 5 и ожидаемых < 2000 тегов).

Иллюстрация подсчёта счётчиков (файлы; для сегментов/меток — аналогично):

```sql
WITH RECURSIVE d(root, tag_id) AS (
  SELECT id, id FROM tags
  UNION ALL
  SELECT d.root, t.id FROM tags t JOIN d ON t.parent_id = d.tag_id
)
SELECT d.root AS tag_id, COUNT(DISTINCT vt.video_id) AS files
FROM d JOIN video_tags vt ON vt.tag_id = d.tag_id
GROUP BY d.root;
```

## 4. Изменения контрактов

### 4.1. API (существующие контракты §4 конвенций + уточнения)

| Метод | Path | Что делаем | Статус |
|---|---|---|---|
| GET | `/api/tags/tree` | дерево + счётчики; `?include_counts=1` | контракт §4 конвенций, форма ответа уточняется здесь |
| POST | `/api/tags` | `{parent_id?, name, color?}` → `201` + созданный узел | контракт есть |

| POST/DELETE | `/api/segments/{id}/tags`, `/api/segments/{id}/tags/{tag_id}` | назначить/снять тег сегмента | контракт `00` §4 |

| GET | `/api/search` | `tag:<имя>`/`tag:"<путь>"`, `tag_ids`, `tag_mode` (по умолчанию `any`, `00` §4.1 п.2), `include_children=1` | контракт `00` §4.1 п.2 |

Форма `GET /api/tags/tree` (списочный ответ §4 конвенций — `{items,total}`):

```json
{
  "items": [
    {"id": 1, "parent_id": null, "name": "Учёба", "color": "#2563eb", "depth": 0,
     "counts": {"files": 2, "segments": 4, "annotations": 0, "children": 1},
     "children": [
       {"id": 2, "parent_id": 1, "name": "Математика", "color": null, "depth": 1,
        "counts": {"files": 2, "segments": 4, "annotations": 0, "children": 0}, "children": []}
     ]}
  ],
  "total": 2
}
```

Ошибки: `400 invalid_tag_name`, `400 tag_depth_exceeded`, `400 tag_cycle`, `404 tag_not_found`, `409 tag_name_conflict`; формат `{detail, code}` (§4 конвенций). SSE `tags.changed` получает payload `{rev, action, tag_ids}` (уточнение A5; остальные типы событий не меняются). `GET /api/videos/{id}/segments` — у элемента `segments[]` добавляется `tag_ids: number[]` (M5 читает его для бейджей). Поле `tags_count` в элементах `GET /api/videos` введено в M2 (`./02-library-m2.md` §4.1 и «Открытые вопросы»): M6 сохраняет имя и обеспечивает актуальность после назначения/снятия тега; счётчики по поддереву живут только в `/api/tags/tree`.

### 4.4. Решения по открытым вопросам (ратифицировано Lead'ом)

1. **Глубина тегов:** API-лимит 8 (защита от циклов/патологий), дефолт настройки `tags.max_depth=5`, UI предлагает 5 — `00` §4.1 п.2.
2. **Удаление:** только каскад поддерева (`ON DELETE CASCADE`), режим `reparent` не реализуется.
3. **`tag:` для `scope=segments`:** только собственные теги сегмента; теги файла — через `scope=files`/`/api/videos?tag_ids=`; оператор `video_tag:` не вводится.
4. **Экспорт:** M6 экспортирует дерево тегов; связи `annotation_tags` добавляет M7 в свою схему `version:1` (обратная совместимость).
5. **Переобработка:** `segment_tags` теряются вместе с сегментами — M6 предупреждает в UI подтверждения reprocess, M9 фиксирует в `docs/user-guide.md`; метки и теги файлов сохраняются.
6. **Имя тега:** запрещены `/` и `\` (разделитель пути тега), trim, регистронезависимая уникальность; согласовано с M10 (тест-данные).
7. **`tag_mode` по умолчанию:** `any` (объединение) и для `/videos`, и для `/search`; `all` — явный параметр (`00` §4.1 п.2).

## 6. UI/UX-спецификация

**Компоненты.**

| Компонент | Назначение | Зависит от |
|---|---|---|
| `TagTree` | дерево тегов, навигация, DnD-приёмник для перемещения | `tagsStore`, `useTags` |
| `TagTreeItem` | узел: раскрытие, имя, счётчик, swatch цвета, состояния hover/selected/drop-target | — |
| `TagFilterChips` | активные фильтры, `×`, переключатель объединение/пересечение | `settings` |
| `TagPicker` | выбор/создание тегов (сегменты, метки M7) | `api/client` |
| `TagContextMenu` | CRUD-операции и экспорт/импорт | `ContextMenu` (M1) |
| `TagColorSwatch` | палитра 12 цветов + «без цвета» | `constants.ts` |

**Поведение.**

- Левая панель: два таба — «Файлы» (M2) и «Теги»; активный таб сохраняется в `localStorage` (`vl.ui.sidebarTab`), ширина панели — M2/`useResizable`.
- Обычный клик — одиночный фильтр (снимает предыдущий); `Ctrl+клик` — добавить/убрать тег из набора; `Shift+клик` — диапазон; повторный клик по единственному активному — сброс.
- Режим «Объединять» (`union`, по умолчанию) показывает файлы, у которых есть хотя бы один из выбранных тегов; «Пересекать» (`intersection`) — только файлы со всеми. Режим сохраняется в `settings.tags.multi_select_mode` (уже в M9 — в окне настроек).
- Drag&drop: перетаскивание тега на строку файла назначает тег; на другой тег — перемещает узел (с теми же проверками цикла/глубины); на строку таймингов — назначает тег сегменту. Во время drag — `cursor: grabbing`, подсветка допустимых целей.
- Контекстное меню: «Создать тег…», «Создать дочерний…», «Переименовать» (F2), «Цвет», «Переместить…» (альтернатива drag для доступности), «Удалить…» (диалог с числами), «Экспортировать теги», «Импортировать теги».
- Пустое состояние таба: текст + кнопка «Создать тег».
- Ошибки: toast `error` с текстом из `ru.json`; при `409` — инлайн-подсветка поля имени.

**Клавиши внутри дерева:** `↑/↓` — перемещение фокуса, `→` — раскрыть/первый ребёнок, `←` — свернуть/к родителю, `Enter` — применить фильтр, `Space` — добавить в мультивыбор, `F2` — переименовать, `Delete` — удалить, `Esc` — снять фокус/закрыть меню.

**Доступность:** контраст текста и swatch ≥ 4.5:1 (проверяется в M9); операция назначения доступна без мыши (контекстное меню «Назначить тег…» → `TagPicker`); `aria-live="polite"` для сообщения о результате назначения.
