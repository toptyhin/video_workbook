# 02. M2 — Библиотека и список файлов

> Этап: M2 · Оценка: 2–3 дня · Зависит от: M1 · Разблокирует: M3
> Владелец: writer-core

## 1. Цель и границы

Этап наполняет приложение библиотекой: пользователь добавляет отслеживаемые папки, приложение рекурсивно индексирует видеофайлы, снимает метаданные через `ffprobe`, дедуплицирует по `sha256`, следит за изменениями на диске и показывает список файлов с длительностью, статусами, сортировкой и удалением из индекса. Появляются обе основы будущего UI: дерево папок (таб «Файлы») и таблица файлов.

**Входит в этап:**
- CRUD отслеживаемых folders (`/api/folders`), `/api/fs/list` с жёстким ограничением внутри корней.
- Сканирование (OS-walk, рекурсивно), `ffprobe`-метаданные (`duration_ms`, `size_bytes`), поддержка `mp4/mkv/mov/avi/webm/m4v`, дедупликация `sha256`.
- `watchdog`-наблюдатели за корнями: создание/переименование/удаление файлов, debounce, инкрементальный upsert.
- `GET /api/videos` (фильтры, сортировка, пагинация), `DELETE /api/videos/{id}` (файл на диске не трогать), `GET /api/videos/{id}/thumb`.
- Счётчики папок (`folder_stats`), дерево папок, таблица файлов, мультивыбор, drag&drop из ОС, пустые состояния и ошибки.
- Тесты бэкенда и компонентов, обновление `docs/architecture.md`.

**Не входит (границы):**
- Постановка в очередь и транскрипция (`POST /api/videos/enqueue`, статусы `queued/processing`) — M3.
- Полнотекстовый поиск и `q`-операторы — M4 (в M2 `q` — только подстрока по имени/пути).
- Range-стриминг (`/stream`), плеер, панель таймингов, `GET /segments` — M5.
- CRUD тегов, тегирование, дерево тегов — M6; метки — M7.
- Полный settings-диалог, перетаскиваемые ширины панелей, персист UI-состояния, темы — M9.
- Упаковка ресурсов и `.deb`/`.AppImage` — M8.

## 2. Предусловия

- M1 закрыт: приложение запускается, `/api/health` отвечает, БД с миграциями 001–003 создаётся, SSE-каркас и `/api/settings` работают.
- `scripts/fetch-ffmpeg.sh` выполнен: `resources/ffmpeg/ffprobe` и `ffmpeg` доступны (для dev — из `./resources`, для prod — из `VL_RESOURCES_DIR`).
- Есть тестовый набор видео в tmp-каталоге: валидные `mp4`/`mkv`, файл с неподдерживаемым расширением, битый файл, дубликат по содержимому.
- Рабочая БД может быть пересоздана (миграции M2 не добавляют, см. §4.2).
- Права пользователя позволяют читать тестовые каталоги; для тестов «нет прав» используется `chmod 000` в tmp-каталоге.

## 3. Решения

**D-02.1. Источник истины — БД, диск — источник при сканировании.** `videos` хранит только проиндексированные файлы; дерево строится из `watched_folders` + ленивые подкаталоги через `/api/fs/list`; файлы папки показываются из БД по точному пути каталога. Это даёт быстрый UI и не требует `stat` на каждый рендер.

**D-02.2. Дедупликация.** Быстрый путь — `SELECT` по `path`; для новых файлов считается `sha256` потоково (блоки 8 МиБ). Если хэш уже есть у другой записи — файл не индексируется, инкрементируется счётчик `duplicates`, событие в лог INFO. Хэш не пересчитывается для уже проиндексированных файлов (повторный скан дешёвый). Уникальный индекс `sha256` из `TARGET.md` §4 — страховка от гонки, `IntegrityError` трактуется как дубликат.

**D-02.3. `ffprobe` как отдельный сервис с таймаутом.** Бинарник ищется в `VL_RESOURCES_DIR/ffmpeg/ffprobe`, затем в `PATH`. Вызов: `-v error -print_format json -show_format -show_streams`, таймаут 20 с, запуск из пула потоков (`anyio.to_thread`), не более 4 параллельных вызовов. Ошибка `ffprobe` (битый файл, нет видеопотока, таймаут) не отменяет индексацию: создаётся строка `videos` со статусом `error` и текстом в `error`, чтобы файл был виден в списке с причиной (`TARGET.md` §3.2).

**D-02.4. Скан выполняется в фоне.** `POST /api/videos/scan` возвращает `202` и `scan_id`, сама работа идёт `asyncio.Task` с ограниченным параллелизмом `ffprobe`; прогресс виден через поток `video.status`-событий. Повторный вызов для уже идущего корня возвращает существующий `scan_id` (идемпотентность). Завершение публикует `folder.scanned` — контракт `00` A5 (§4.3).

**D-02.5. Сканирование принимает файл или каталог.** `POST /api/videos/scan {"path": …}` с путём файла индексирует один файл (используется drag&drop и диалогом выбора файлов), с путём каталога — рекурсивно. Путь обязан лежать внутри одного из отслеживаемых корней, иначе `403` (та же проверка, что для `/api/fs/list`).

**D-02.6. `/api/fs/list` — только каталоги.** Возвращает подкаталоги запрошенного пути (для дерева), сортировка по имени, скрытые `.dot`-каталоги скрыты. Файлы для правой таблицы приходят из `/api/videos?folder=…`, поэтому шейп листинга не дублирует метаданные. Проверка: `realpath` запрошенного пути должен быть внутри `realpath` одного из корней; иначе `403`.

**D-02.7. Удаление папки из отслеживаемых не удаляет файлы из индекса.** `DELETE /api/folders/{id}` снимает наблюдение и убирает корень из дерева; записи `videos` и их транскрипты/метки остаются (удаление из индекса — отдельное явное действие `TARGET.md` §3.1). Повторное добавление папки восстанавливает дерево без переиндексации существующих файлов.

**D-02.8. Превью-кадр генерируется лениво и кэшируется.** `GET /api/videos/{id}/thumb` при первом запросе запускает `ffmpeg -ss <5% длительности> -frames:v 1 -vf scale=320:-1 -q:v 4`, пишет атомарно (`*.tmp` + `rename`) в `$VL_DATA_DIR/cache/thumbs/{id}.jpg`, отдаёт JPEG; до готовности — `404`. В `00-conventions.md` §4 эндпоинт отнесён к M5, но список файлов требует превью уже в M2 — распределение зафиксировано в `00` §4.1 п.4: M2 реализует endpoint, M5 использует его без переписывания (расширяет кэш-ключ `sha256+at_ms` и `?at_ms=`).

**D-02.9. Авторизация превью.** `<img src>` не может передать `X-VL-Token`, а исключение для query-токена в `00` §2 (A4) сделано только для `/api/events`. Поэтому в M2 превью загружается через `fetch` с заголовком и превращается в `blob:`-URL (кэш в store, `revokeObjectURL` при размонтировании). Альтернатива — разрешить `?token=` для `/thumb` — требует изменения A4, вынесено в «Открытые вопросы».

**D-02.10. Drag&drop из ОС получает путь через preload.** В sandboxed renderer надёжный способ получить путь — `webUtils.getPathForFile(file)` в preload (новый метод `window.vl.getPathForFile`), с fallback на `File.path` для Electron 31. Это контракт `00` §6 (ратифицировано: `getPathForFile`).

**D-02.11. Фиксированные ширины панелей в M2.** Левая панель — 280 px, панель контента занимает оставшееся место; перетаскивание ширины и сохранение в `localStorage` относятся к `TARGET.md` §2.2 и реализуются в M9 (`00` A12). M2 не создаёт UI-состояние, которое придётся мигрировать.

## 4. Изменения контрактов

### 4.1. API

| Метод | Путь | Статус | Что фиксирует этап |
|---|---|---|---|
| GET | `/api/folders` | контракт `00` §4 | `{"items":[{"id":1,"path":"/…","added_at":"…","total":10,"done":3}],"total":1}`; `total/done` — агрегат по поддереву |
| POST | `/api/folders` | контракт `00` §4 | `{"path":"/…"}`, `201` + объект папки; несуществующий/нечитаемый путь — `400`; повтор — `409` |
| DELETE | `/api/folders/{id}` | контракт `00` §4 | `204`; файлы индекса не удаляются; фоновые задачи скана корня отменяются |
| GET | `/api/fs/list` | шейп — контракт `00` §4 | `?path=`; `{"path":"…","parent":"…","entries":[{"name":"math","path":"…","mtime_ms":0,"watched":false}]}`; только каталоги |
| POST | `/api/videos/scan` | шейп/асинхронность — контракт `00` §4 (202 + `folder.scanned`) | `{"path":"…"}` (файл или каталог) → `202 {"scan_id":"…","state":"running","root":"…"}`; вне корней — `403` |
| GET | `/api/videos` | шейп элемента — контракт `00` §4.1 | параметры `folder` (точный каталог), `tag_ids` (CSV), `status` (CSV), `q` (подстрока), `sort`, `dir`, `limit`, `offset`; `{items,total}` |
| DELETE | `/api/videos/{id}` | контракт `00` §4 | `204`; каскадное удаление `segments`/`annotations`/связей; thumb-файл удаляется; файл на диске не трогается |
| GET | `/api/videos/{id}/thumb` | контракт `00` §4 (реализация — M2, M5 расширяет `?at_ms=`) | `200 image/jpeg` из кэша, иначе генерация; `404` пока кадр не готов |

Элемент списка файлов (M2), **контракт `00` §4.1**:

```json
{"id":3,"path":"/home/u/lessons/a.mp4","title":"a.mp4",
 "duration_ms":754000,"size_bytes":123456789,"status":"pending",
 "progress":0,"error":null,"tags_count":0,
 "mtime_ms":1712000000000,
 "added_at":"2026-10-26T17:00:00Z","processed_at":null}
```

Сортировка: whitelist `title|duration_ms|size_bytes|status|added_at|mtime_ms|progress`, `dir=asc|desc`; `limit` по умолчанию 50, максимум 500; `offset` ≥ 0. Неизвестный `sort`/`status` → `400`.

### 4.2. БД

Новых миграций нет: используются таблицы из 001–003 и колонки из 002 (`lang`, `model`, `headline` появятся в M3). `folder_stats` заполняется сервисом статистики; `total` — число проиндексированных файлов в каталоге, `done` — со статусом `done`. Расширять `folders`/`videos` в M2 не требуется.

Статусы `videos.status` в M2: `pending`, `error`, `duplicate`, `missing` (готово для M3: `queued`, `processing`, `done`); `duplicate` — файл пропущен по `sha256`, `missing` — файл исчез с диска (watcher), запись сохраняется до ручного удаления.

### 4.3. SSE

| Событие | Статус | Payload |
|---|---|---|
| `video.status` | контракт A5 | `{"video_id":3,"status":"pending","error":null}` — для добавленных/изменённых/ошибочных файлов |
| `backend.error` | контракт A5 | `{"code":"scan_failed","detail":"…","scan_id":"…"}` |
| `folder.scanned` | контракт `00` A5 | `{"scan_id":"…","root":"…","found":10,"added":9,"duplicates":1,"errors":0,"duration_ms":1234}` |
| `video.progress`/`queue.state` | контракт A5 | зарезервированы M3, в M2 не публикуются |

### 4.4. Preload / IPC

| Метод | Статус | Назначение |
|---|---|---|
| `getPathForFile(file: File): string` | контракт `00` §6 (ратифицировано) | путь файла из drag&drop (`webUtils.getPathForFile`), fallback `File.path` |

`getPathForFile` не является IPC-каналом: это синхронный метод `webUtils` в preload, экспортируется через `contextBridge`; в `00` §6 его нет, расширение контракта согласуется отдельно.

### 4.5. Прочее

- Новые ключи `settings` в M2 не вводятся; корни хранятся в `watched_folders` (`TARGET.md` §4).
- `q` в M2 — только подстрока `LOWER(title|path) LIKE`; FTS5 и операторы `AND/OR/NOT` — M4, контракт `/api/search` не меняется.

## 5. Задачи

### T-02.1. Отслеживаемые папки и безопасный `/api/fs/list`
**Файлы:** `backend/app/routers/folders.py`, `backend/app/routers/fs.py`, `backend/app/services/folders_service.py`, `backend/app/utils/paths.py`, `backend/app/models.py`, `backend/tests/test_folders.py`, `backend/tests/test_fs_list.py`.
**Что сделать:**
1. `POST /api/folders`: `realpath`, проверка `exists`/`is_dir`/`os.access(R_OK)`; запись в `watched_folders`; `201` + объект; дубль — `409`; путь внутри другого корня — разрешён (вложенные корни допустимы).
2. `GET /api/folders`: список с `total`/`done`, агрегированными по поддереву из `folder_stats` (`folder_path = … OR LIKE prefix`), сортировка по `path`.
3. `DELETE /api/folders/{id}`: `404` при отсутствии, `204` при успехе; останавливает наблюдатель корня (M2.3) и снимает задачи скана этого корня; записи `videos` остаются.
4. `GET /api/fs/list`: только каталоги, сортировка по имени, скрытые `.dot` пропускаются; ответ `{path, parent, entries}`; путь вне корней — `403 {"detail":"path outside watched roots"}`; несуществующий — `404`; `parent=null` для корней.
5. `utils/paths.py`: `normalize`, `is_within_roots` (realpath + `Path.is_relative_to`), обработка symlink-побегов наружу; `models.py` — pydantic-схемы folder/fs.
6. Тесты: CRUD, конфайнмент (`../`, абсолютный путь вне корня, symlink наружу, вложенный корень), скрытые каталоги, сортировка, лимит вложенности не ограничен.
**Готово, когда:** добавили `/tmp/lessons` → дерево получает корень; `/api/fs/list?path=/tmp/lessons` отдаёт подкаталоги; запрос `/etc` — `403`; удаление корня не удаляет записи `videos`.
**Оценка:** 0.35 д.

### T-02.2. `ffprobe`-метаданные, сканирование и дедупликация `sha256`
**Файлы:** `backend/app/services/probe.py`, `backend/app/services/scanner.py`, `backend/app/utils/sha256.py`, `backend/app/routers/videos.py` (только `/scan`), `backend/app/models.py`, `backend/tests/test_probe.py`, `backend/tests/test_scan.py`, `backend/tests/fixtures/` (fake `ffprobe`, тестовые видео).
**Что сделать:**
1. `probe.py`: `resolve_ffprobe()` (resources → PATH), `probe(path) -> ProbeResult` с `duration_ms`, `size_bytes`, `has_video`; JSON-парсинг, таймаут 20 с, `ProbeError(code, detail)`; аудио-файл без видеопотока — ошибка `no_video_stream`.
2. `sha256.py`: потоковое хэширование 8 МиБ-блоками, отмена по прерыванию, `hexdigest`.
3. `scanner.py`: `scan_path(path, scan_id) -> ScanStats` — файл или каталог (D-02.5); `os.scandir` с фильтром расширений (без регистрозависимости), скрытые каталоги и symlinked-каталоги пропускаются; на файл — `SELECT` по path, `sha256`, проверка дубликата, `probe`, `INSERT`; `ffprobe`-ошибка → строка `status=error`, `error=detail`; `IntegrityError` — дубликат.
4. `POST /api/videos/scan`: запуск в `asyncio.Task`, реестр `scan_id → task` с блокировкой, ответ `202`; по завершении `EventBus.publish("folder.scanned", stats)`; публикация `video.status` на каждый добавленный/ошибочный файл.
5. Ограничение параллелизма: `ffprobe`/`sha256` — в `anyio.to_thread` с семафором 4; суммарно не блокировать event loop (тест с искусственной задержкой 0.5 с на файл, параллельный `/api/health` отвечает < 300 мс).
6. Фикстуры: shell-скрипт fake `ffprobe` (успех/ошибка/таймаут), маленькие файлы (сгенерированные в `conftest` через реальный ffmpeg, с `skip`, если бинарника нет), `broken.mp4` (мусор с расширением), дубликат-копия.
7. Тесты: 3 файла → 3 строки с `duration_ms`; копия → `duplicates=1`, строк не прибавилось; `.txt` игнорируется; `broken.mp4` → `status=error`; скан файла; скан вне корня — `403`; повторный скан — без новых строк и без повторного хэширования (проверка по моку).
**Готово, когда:** тесты сканера зелёные; `/api/videos` (после M2.4) содержит длительности; `docs/architecture.md` дополнен схемой «скан → probe → БД».
**Оценка:** 0.5 д.

### T-02.3. `watchdog`-наблюдатели и счётчики `folder_stats`
**Файлы:** `backend/app/services/watcher.py`, `backend/app/services/stats.py`, `backend/app/main.py` (lifespan), `backend/tests/test_watcher.py`, `backend/tests/test_stats.py`.
**Что сделать:**
1. `watcher.py`: `WatcherManager` — `watchdog.observers.Observer` на каждый корень, `FileSystemEventHandler` с фильтром расширений; события `created`/`moved`/`closed_write` → debounce 1.5 с на путь, затем upsert (probe + insert/update); `deleted` → лог WARNING + удаление thumb-кэша, строка `videos` не удаляется (см. «Открытые вопросы»).
2. Переименование внутри корней (пары `moved`) → `UPDATE videos SET path=…` для существующей записи, иначе insert; переименование за пределы корней — запись остаётся, лог.
3. Мост из observer-потока в event loop: `asyncio.run_coroutine_threadsafe`; ошибки обработки — `backend.error` с ограничением частоты; повтор до 3 раз.
4. `stats.py`: `recalc_folder_stats(root)` — подсчёт `total`/`done` по всем каталогам с индексированными файлами; debounce 5 с; вызовы после скана, upsert, смены статуса; ручной пересчёт по `POST /api/videos/scan` завершению.
5. Lifespan: старт наблюдателей для существующих корней; реакция на `POST/DELETE /api/folders` (перестроить наблюдатели без рестарта приложения); корректный `stop()` при shutdown.
6. Тесты: создание файла в watched-каталоге → строка `pending` за ≤ 5 с (polling); переименование → `path` обновлён; удаление → строка на месте, thumb удалён; `folder_stats` пересчитан; добавление корня через API запускает наблюдение.
**Готово, когда:** новые файлы появляются в БД без ручного скана; `GET /api/folders` показывает актуальные `total/done`; остановка приложения не оставляет потоков `Observer` (тест на shutdown).
**Оценка:** 0.4 д.

### T-02.4. Список файлов, удаление из индекса и превью-кадр
**Файлы:** `backend/app/routers/videos.py`, `backend/app/services/thumbnail.py`, `backend/app/models.py`, `backend/tests/test_videos_list.py`, `backend/tests/test_thumbnail.py`.
**Что сделать:**
1. `GET /api/videos`: фильтры `folder` (точное совпадение каталога, без рекурсии), `status` (CSV), `q` (подстрока по `title`/`path` через `LOWER LIKE`), `tag_ids` (CSV, join `video_tags`; в M2 таблица пуста), сортировка по whitelist (§4.1), `limit`/`offset`, ответ `{items,total}`; `400` на неизвестные значения.
2. Шейп элемента по §4.1, `tags_count` через `LEFT JOIN` (`0` до M6); добавить `HEAD`-совместимость не требуется.
3. `DELETE /api/videos/{id}`: транзакция — `DELETE FROM videos` (каскады по FK), удаление `cache/thumbs/{id}.jpg`; `204`; файл на диске проверяется тестом (`os.path.exists` после удаления).
4. `thumbnails.py` + `GET /api/videos/{id}/thumb`: кэш по `id` (инвалидация при `mtime`/переобработке), генерация `ffmpeg` с таймаутом 20 с, атомарная запись, `404 {"detail":"thumb unavailable"}` при ошибке/отсутствии файла; заголовки `Cache-Control: private, max-age=86400`.
