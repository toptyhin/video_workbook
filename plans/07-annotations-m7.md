# 07. M7 — Метки на видео (annotations) и поиск по меткам

> Этап: **M7** · Оценка: **3–4 дня (24–32 ч)** · Зависит от: **M4, M5, M6** · Разблокирует: **M8, M9, приёмку**
> Владелец: Lead · Контракты: `./00-conventions.md` §4–§7
>
> Пользовательское требование (обязательное): элементы управления для **ручной простановки собственных меток по видео** и **поиск по этим меткам**. Этот план — основной носитель требования; см. также `./00-conventions.md` §12.

## 1. Цель и границы

**Цель.** Дать пользователю полный, быстрый и предсказуемый контур ручной разметки видео: создать метку (на позиции, перетаскиванием по таймлайну, из выделенного диапазона строк), отредактировать (текст, цвет, теги, заметка, границы), удалить (с undo), увидеть её на таймлайне и в панели таймингов, а также **найти метки** по тексту, тегу, цвету и видео — с переходом на её таймкод и подсветкой.

**В объёме:**

- БД: `annotation_tags` (исправляет G1), `annotations_fts` (G3), `updated_at`, индексы; миграции 005 и 006.
- API: CRUD `/api/annotations`, `POST /api/annotations/bulk`, `GET /api/annotations/export`, `POST /api/annotations/import`; расширение `/api/search` (`scope=annotations`, `kind:"annotation"`, фильтры `tag_ids`/`colors`/`video_id`).
- UI: слой маркеров на таймлайне, ручки `resize`, drag-создание диапазона, контекстное меню, панель «Метки» с фильтрами, диалог редактора, строки меток в панели таймингов, клавиатурные сокращения, undo/redo.
- Теги меток через `annotation_tags` и `TagPicker` из M6.
- События `annotations.changed` по SSE для консистентности списков после bulk-операций и импорта.
- Экспорт/импорт меток в JSON (обмен между копиями библиотеки).

**Не в объёме (границы):**

- Автоматическая расстановка меток (ML, детекция сцен, кластеризация речи) — вне объёма проекта.
- Экспорт меток в главы видеофайла (`ffmpeg -chapter`), WebVTT/SRT — stretch после M9 (Q6).
- Синхронизация меток между устройствами, многопользовательская работа, права доступа.
- Метки на нескольких видео одновременно, глобальные метки без привязки к видео.
- Изменение механики транскрипции/поиска по сегментам (M3/M4), кроме расширения `scope`.
- Свободное рисование на кадре, комментарии с ответами, вложения.

## 3. Решения

**D1. Метка — независимый интервал.** `annotations` не ссылается на сегмент: `start_ms`/`end_ms` — самостоятельные величины. Snap к границам сегментов — только UX-помощь (храним точные значения, snap вычисляется на клиенте). Это позволяет размечать паузы, музыку, тишину и произвольные фрагменты.

**D2. Сервер — источник истины, UI — оптимистичный.** Создание/правка/удаление применяются в сторе сразу (временный отрицательный `id` для create), затем подтверждаются ответом. При ошибке — откат + toast. При `annotations.changed` — точечный refetch (`GET /annotations?video_id=`), чтобы не терять выделение и позицию плеера.

**D3. Undo/redo на клиенте, стек 50, только операции с метками.** Команды: `create` (undo → `DELETE`, redo → повторный `POST` с новым id и привязкой тегов), `update` (undo/redo → `PATCH` прежних/новых полей), `delete` (undo → `POST` с сохранёнными полями и тегами, id новый). Undo не отменяет теги/импорт целиком и не влияет на сегменты. Кнопки в тулбаре + `Ctrl+Z`/`Ctrl+Shift+Z`.

**D4. Единая модель времени и валидация.** Время — целые миллисекунды. Инварианты: `0 <= start_ms < end_ms <= duration_ms`, `end_ms - start_ms >= 300` (минимальная длина), `label = trim` 1…200 символов, `note <= 2000`, `color` — `#rrggbb`. Валидация дублируется на сервере (источник истины) и на клиенте (мгновенная обратная связь). Ошибки — коды из §4, на русском в UI.

**D5. Создание тремя путями.** (а) `Ctrl+M`/кнопка — интервал `[playhead, playhead + 5000]`, обрезанный по `duration_ms`; (б) drag по таймлайну — интервал от точки нажатия до точки отпускания с порогом 4 px (иначе — клик/seek); (в) выделение строк в панели таймингов → `Ctrl+M`/«Создать метку» → `POST /annotations/bulk` (одна метка на непрерывный диапазон строк; разрывы разбиваются на диапазоны). После создания диалог открывается в режиме «сразу сохранить»: метка уже существует, диалог правит её поля (так пользователь видит результат немедленно).

**D6. Snap и точность drag.** Сетка 1 с + границы сегментов (радиус 8 px), `Alt` отключает snap. Индикатор snap — вертикальная подсветка линии таймлайна + tooltip с временем. Точность попадания в результат — ±100 мс (критерий R4). При drag-создании и resize применяется `clamp` к `[0, duration_ms]` и минимальная длина D4.

**D7. Цвета и доступность.** 8 предустановленных цветов (`#3b82f6 #22c55e #eab308 #f97316 #ef4444 #a855f7 #14b8a6 #64748b`) + произвольный `#rrggbb`; цвет метки используется для маркера на таймлайне, левой полосы строки и чипа в результатах поиска. Контраст текста на фоне цвета проверяется утилитой `pickReadableTextColor(hex)`. Цвет не кодирует смысл в одиночку: всегда есть подпись/иконка 🏷 (доступность).

**D8. Поиск по меткам — часть единого поиска.** FTS-таблица `annotations_fts` по `label` и `note` (веса bm25: label 2.0, note 1.0); `scope=annotations` ограничивает выдачу; `kind:"annotation"` в общем потоке. Текстовый запрос — FTS5; `tag:<имя>` фильтрует по тегам метки (с дочерними тегами); `colors` — фильтр по цвету; `video_id` — по видео. Пустой запрос при `scope=annotations` = список меток с фильтрами (для панели «Метки»).

**D9. Панель «Метки» — отдельный режим списка, а не модалка.** Левая/центральная область переключается в режим «Метки» (вкладка), где список всех меток библиотеки с фильтрами и сортировкой; двойной клик — открыть видео и перейти на `start_ms`; удаление/правка — из строки. Это закрывает требование «поиск по меткам» и даёт управление ими вне конкретного видео.

**D10. Производительность маркеров.** Базовый рендер — DOM-слой, как в M5 D6: абсолютно позиционированные `div` с `transform: translateX`, без re-render всех при движении playhead; маркеры обновляются батчем по `requestAnimationFrame`. Цель: 300 маркеров, ≥ 50 fps при drag, без просадок playback. Canvas-слой — только contingency: если бенчмарк M7 стабильно ниже 50 fps, решение согласуется с M5 (владелец таймлайна) и фиксируется в `docs/architecture.md`; по умолчанию DOM. `TimingPanel` — виртуализация списка при > 500 строк (метки + сегменты).

**D11. Импорт/экспорт JSON с версией схемы.** `version: 1`; экспорт одного видео или всей библиотеки; импорт — merge по умолчанию (не дублирует идентичные интервалы/подписи), `mode:"replace"` удаляет прежние метки видео. Конфликты тегов решаются по имени (создаются при отсутствии). Операция возвращает отчёт `{imported, skipped, errors[]}`.

## 4. Изменения контрактов

Все изменения согласованы с `./00-conventions.md` §4, §5; помеченных «новое, требует согласования» нет.

### 4.1. Миграции

```sql
-- 006_annotation_tags.sql
CREATE TABLE annotation_tags (
  annotation_id INTEGER NOT NULL REFERENCES annotations(id) ON DELETE CASCADE,
  tag_id        INTEGER NOT NULL REFERENCES tags(id)        ON DELETE CASCADE,
  PRIMARY KEY (annotation_id, tag_id)
);
CREATE INDEX idx_ann_tags_tag ON annotation_tags(tag_id);

-- 007_annotations_fts.sql
ALTER TABLE annotations ADD COLUMN updated_at TEXT;
CREATE VIRTUAL TABLE annotations_fts USING fts5(
  label, note, content='annotations', content_rowid='id',
  tokenize='unicode61 remove_diacritics 2'
);
CREATE TRIGGER annotations_ai AFTER INSERT ON annotations BEGIN
  INSERT INTO annotations_fts(rowid, label, note) VALUES (new.id, new.label, new.note);
END;
CREATE TRIGGER annotations_ad AFTER DELETE ON annotations BEGIN
  INSERT INTO annotations_fts(annotations_fts, rowid, label, note)
  VALUES ('delete', old.id, old.label, old.note);
END;
CREATE TRIGGER annotations_au AFTER UPDATE ON annotations BEGIN
  INSERT INTO annotations_fts(annotations_fts, rowid, label, note)
  VALUES ('delete', old.id, old.label, old.note);
  INSERT INTO annotations_fts(rowid, label, note) VALUES (new.id, new.label, new.note);
END;
CREATE INDEX idx_ann_start ON annotations(start_ms);
```

После создания таблиц — `INSERT INTO annotations_fts(annotations_fts) VALUES('rebuild')` для существующих строк (идемпотентно на старте миграции).

### 4.2. API `/api/annotations`

| Метод | Path | Тело запроса | Ответ |
|---|---|---|---|
| GET | `/annotations` | query: `video_id`, `tag_id` (повторяемый), `color`, `q`, `limit`, `offset` | `{items:[Annotation], total}` |
| POST | `/annotations` | `{video_id, start_ms, end_ms, label, color?, note?, tag_ids?}` | `201 Annotation` |
| POST | `/annotations/bulk` | `{video_id, items:[{start_ms, end_ms, label, color?, note?, tag_ids?}]}` | `201 {items:[Annotation], total}` |
| GET | `/annotations/{id}` | — | `Annotation` |
| PATCH | `/annotations/{id}` | любое подмножество полей; `tag_ids` заменяет набор целиком; `updated_at` ставится сервером | `Annotation` |
| DELETE | `/annotations/{id}` | — | `204` |
| GET | `/annotations/export` | query: `video_id?` | `{version:1, exported_at, video?, annotations:[…]}` |
| POST | `/annotations/import` | `{video_id?, data, mode:"merge"\|"replace"}` | `{imported, skipped, errors[]}` |
| GET | `/search` | `q`, `scope=annotations`, `video_id`, `tag_ids`, `colors`, `limit`, `offset` | элементы `kind:"annotation"` |

`Annotation` (JSON):

```json
{
  "id": 7, "video_id": 3, "start_ms": 30000, "end_ms": 75000,
  "label": "важный пример", "color": "#3b82f6", "note": "производная сложной функции",
  "tag_ids": [2, 5], "created_at": "2026-10-26T12:00:00Z", "updated_at": "2026-10-26T12:00:00Z"
}
```

Элемент поиска `kind:"annotation"` — из `./00-conventions.md` §4 (содержит `annotation_id`, `start_ms`, `end_ms`, `label`, `note`, `color`, `tag_ids`, `snippet_html`, `score`).

### 4.3. Коды ошибок

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `annotation_invalid_range` | `start_ms >= end_ms`, отрицательные, выход за `duration_ms`, короче 300 мс |
| 400 | `annotation_empty_label` / `annotation_label_too_long` | пустая после trim / > 200 |
| 400 | `annotation_note_too_long` | > 2000 |
| 400 | `annotation_invalid_color` | не `#rrggbb` |
| 404 | `annotation_not_found`, `video_not_found` | нет сущности |
| 409 | `annotation_conflict` | импорт с `mode:"replace"` при активной обработке видео (защита от гонки) |

### 4.4. SSE

Событие `annotations.changed`: `{ "page": "/api/annotations", "data": {"video_id": 3, "op": "create|update|delete|bulk|import", "ids": [7, 8]}}`. Клиент делает точечный refetch; плеер и панели не сбрасываются.

### 6.2. Геометрия и стили

- Маркер: высота 8 px, скругление 2 px, `top: 50%` слоя с `translateY(-50%)`; активный — обводка 2 px `--vl-focus`, `box-shadow`; минимальная ширина 4 px; при перекрытии — суммарная полоса с бейджем количества.
- Выделенный drag-диапазон: `background: rgba(59,130,246,0.25)`, границы 1 px; snap-линия — 2 px `--vl-accent` с `will-change: transform`.
- Строка метки в панели: левая полоса 3 px цветом метки; активная — фон `--vl-selected`; фокус — `outline: 2px solid var(--vl-focus)`.
- Чип результата поиска: цветной квадрат 10×10 + текст; контраст текста на цвете — `pickReadableTextColor`.
- Тёмная тема: цвета меток не меняются (они заданы пользователем), фон/текст — из токенов M9.

### 6.3. Состояния и пустые экраны

- Нет видео — панель «Метки»: «Откройте видео, чтобы увидеть и создать метки».
- Нет меток у видео — в панели таймингов: «Меток пока нет. Выделите фрагмент и нажмите ＋ метка».
- Поиск без результатов — «Ничего не найдено по запросу “…”» + подсказка про `tag:`.
- Ошибка загрузки/сохранения — toast с кнопкой «Повторить» (одна попытка).
- Загрузка списка — skeleton-строки (3 шт.), не спиннер на весь экран.

### 6.5. Доступность

- Диалог: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, ловушка фокуса, возврат фокуса.
- Маркеры: `role="button"`, `aria-label="Метка «важный пример», 00:30–01:15, цвет синий"`, фокусируемы `Tab`, активация `Enter`, удаление `Delete`.

- Контраст ≥ 4.5:1 (проверка токенов в M9); цвет метки дублируется текстовой меткой (не только цветом).
