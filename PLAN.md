# PLAN: VideoLessons — мастер-план реализации

> **Что это.** Анализ исходной спецификации `TARGET.md` (в задаче пользователь называет этот документ PLAN.md) и мастер-план реализации: архитектурные решения, разбиение на этапы, индекс файлов с детальными планами, матрица приёмки и риски.
>
> **Статус.** Планы согласованы; реализация M1–M7 завершена и покрыта тестами, M8/M9/A — частично (см. §15 «Статус реализации»).
>
> **Как читать.** §1–2 — что в спеке есть и чего не хватает; §3–4 — решения и контракты; §5–7 — роадмап и покрытие требования про метки; §8 — приёмка; §9–12 — риски, сборка, допущения; §13 — индекс файлов.

## 0. Резюме

**Продукт.** Локальное десктопное приложение «VideoLessons» для Ubuntu: индексирует папки с видеоуроками, локально транскрибирует их на CPU (`faster-whisper`), даёт полнотекстовый поиск по произнесённым словам, синхронизированный плеер с панелью таймингов, иерархические теги и **пользовательские метки на фрагменты видео с поиском по этим меткам**. Поставляется как `.deb` + `.AppImage`, без Python/ffmpeg/сети у пользователя.

**Состав плана.** 1 мастер-план (этот файл) + 11 файлов планов: `plans/00-conventions.md` (контракты и шаблон), `plans/01…09` (этапы M1–M9), `plans/10-acceptance-ci.md` (приёмка и CI).

**Ключевой акцент задания.** Пользователь отдельно потребовал элементы управления для **ручной простановки своих меток по видео** и **поиск по ним**. В спеке метки описаны фрагментарно (§2.4, §3.5), а поиска по меткам нет вовсе. В плане это закрыто: полный UI-контур меток (`plans/07-annotations-m7.md`), расширение поиска `scope=annotations` (`plans/04-search-m4.md`), теги меток (`plans/06-tags-m6.md`), горячие клавиши и доступность (`plans/09-polish-m9.md`). См. §7.

**Оценка.** 9 этапов, 18–27 рабочих дней одного агента + 2 дня приёмки (`plans/10`). Порядок строго последовательный: M1 → M9.

### 2.1. Требование пользователя: ручные метки + поиск по ним

В спеке есть заготовки: кнопка `＋ метка`, кликабельность меток, drag границ на таймлайне (§2.4), модель `annotations` (§3.5). Чего **не было** и что добавлено планом:

| Нужно | В спеке было | Добавлено планом |
|---|---|---|
| Создать метку на текущей позиции плеера | частично (§2.4) | `Ctrl+M`, кнопка `＋ метка`, диалог с валидацией — M7 |
| Создать метку перетаскиванием по таймлайну | нет | drag-выделение диапазона с превью и snap — M7 |
| Создать метку из выделенного диапазона строк таймингов | да (§2.4) | `POST /api/annotations/bulk` + мультивыбор — M7 |
| Редактировать границы перетаскиванием | упомянуто одной строкой | ручки `resize` (start/end), мин. длительность 300 мс, clamp, undo — M7 |
| Цвет, теги и заметка метки | частично (цвет/теги/заметка в диалоге) | палитра 8 цветов + свой, `annotation_tags`, `TagPicker` — M6/M7 |
| Панель управления метками (список/фильтры/удаление/экспорт) | нет | панель «Метки» + контекстные меню + `annotations/export|import` — M7 |
| Поиск по меткам (текст label/note) | нет | `scope=annotations`, `annotations_fts`, `kind:"annotation"` — M4/M7 |
| Поиск по тегам меток | нет | `tag:` в поиске, фильтр `tag_ids` — M6/M7 |
| Переход из результата поиска на таймкод метки с подсветкой | нет | клик по результату → seek + подсветка маркера/строки — M7 |
| Горячие клавиши и доступность | частично (§3.7) | `Ctrl+M`, `Shift+I/O`, `Delete`, `Ctrl+Z/Y`, окно «О клавишах», aria-контракт — M7/M9 |

### 2.2. Ратифицированные решения (по итогам ревью авторских планов)

Авторские планы этапов поднимали контрактные вопросы (14 пробелов от writer-core, 9 от writer-search, 10 от writer-release). Все решения приняты Lead'ом и внесены в `plans/00-conventions.md` §2, §4.1, §5, §6, §7 и в соответствующие планы:

1. **Форма `/api/settings`** — плоский объект, частичный `PATCH`, ключи `language`, `whisper_model`, `theme`, `tags.multi_select_mode`, `tags.max_depth`, `log.level`, `ui.sort`; `settings.changed {keys:[…]}`. Унифицировано между M1/M3/M6/M9 (`00` §4.1 п.1).
2. **`/api/videos/{id}/thumb`** — реализует M2 (ленивый кэш), M5 только расширяет `?at_ms=`; дублирования сервиса нет (`00` §4.1 п.4).
3. **Query-токен** — только для `/api/events` и `/api/videos/{id}/stream`; превью — `fetch`+`blob` (A4). Media-ответы — `Referrer-Policy: no-referrer`.
4. **SSE** — общий конверт `{type, ts, payload}`; события `folder.scanned`, `tags.changed`, `annotations.changed` включены в A5.
5. **`videos.progress`** — доля `0..1`; статусы расширены `duplicate` и `missing`; добавлен `videos.mtime_ms` для колонки «Дата изменения» (`00` §5).
6. **Миграции** — `001–003` M1, `004` M4, `005` M6 (теги), `006–007` M7 (annotation_tags, annotations_fts); номера не переиспользуются.
7. **Скан** — фоновый `202 {scan_id}`, идемпотентность по корню, завершение — `folder.scanned`; формы `/queue`, `/enqueue`, `/cancel`, `/reprocess` закреплены в `00` §4.
8. **Теги** — `tag_mode=any` по умолчанию (и для `/videos`, и для `/search`), `include_children=1`; API-глубина ≤ 8 при дефолте `tags.max_depth=5`; `PATCH /tags/{id}` принимает `parent_id`; сегментные теги `POST/DELETE /api/segments/{id}/tags` — в контракте.
9. **`window.vl`** — только через слой `frontend/src/api/*`; добавлен `getPathForFile` для drag&drop (`00` §6).
10. **Сборка** — Node 20 LTS + Electron 31 (pinned), ffmpeg с приоритетом **LGPL-сборки**, модель в пакете только `small` (A11); `THIRD-PARTY-NOTICES.md`, SUID `chrome-sandbox`, `release.json` — обязательны.
11. **Приёмка/CI** — `scripts/measure*.sh`, `vm-smoke.sh`, `docs/acceptance.template.md`, коды выхода `0/1/2`; `--acceptance-mode` не вводится; `--no-sandbox` — только в тест-контейнере, не в артефакте.
12. **Синхронизация M6↔M7** — guard `annotation_tags` в счётчиках тегов и `scope=annotations` снимается в M7 (T-07.1/T-07.2); экспорт тегов меток — зона M7.

## 3. Архитектурные решения (сводка)

Полный список ADR — `plans/00-conventions.md` §2. Ключевое:

- **Sidecar-архитектура.** Electron main запускает Python-бэкенд (PyInstaller `--onedir`), ждёт `VL_READY:{"port":N}` ≤ 15 с, передаёт `VL_TOKEN`. Рендерер грузит SPA **с бэкенда** (`http://127.0.0.1:<port>/`), поэтому нет CORS и `file://`-ограничений (A1, A3).
- **Безопасность.** `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`; единственный мост — `window.vl` (A2). Токен обязателен для всех `/api/*`; для SSE — query-параметр (A4). Бэкенд слушает только loopback, порт динамический.
- **Транскрипция.** `ProcessPoolExecutor(max_workers=1)`; event loop не блокируется; FIFO-очередь; SSE-прогресс; crash-recovery `processing → queued`; отмена с grace 3 с (A6).
- **Данные.** SQLite WAL + forward-only миграции; FTS5 для сегментов и меток; единый поисковый контракт `kind` (A7–A9).
- **Сборка.** Только Docker `ubuntu:22.04`; ffmpeg/ffprobe и модель в `extraResources`; `.deb` + `.AppImage` (A10–A11).
- **Quality gates.** pytest/vitest/Playwright, CI в Docker, приёмка на чистой Ubuntu (A14, `plans/10`).

```
M1 → M2 → M3 → M4 ─┐
```

## 6. Краткое содержание этапов

- **M1. Скелет.** Репозиторий, Electron main+preload, spawn sidecar с handshake, `/health`, миграции, `/api/events` каркас, `/api/settings`, логи, dev-скрипты, Docker-образ для сборки (заготовка). Без библиотеки и UI-логики.
- **M2. Библиотека.** Watched folders, `fs/list`, scan+watchdog, ffprobe, sha256-дедуп, `/videos` с сортировкой/фильтрами, дерево папок, список файлов со статусами, удаление из индекса, превью-кадр.
- **M3. Транскрипция.** ffmpeg → 16 кГц mono WAV, faster-whisper `small` INT8, пул из 1 процесса, FIFO-очередь, прогресс SSE, отмена, переобработка, crash-recovery, сегменты и метаданные.
- **M4. Поиск.** FTS5 по сегментам и именам, санитайзер запроса, префиксы `tag:`/`file:`, `/search` с `scope` и `kind`, сниппеты и подсветка, панель результатов, debounce 300 мс.
- **M5. Плеер и тайминги.** `<video>` + Range 206, thumbnails, панель таймингов с активным сегментом и автопрокруткой, таймлайн с блоками сегментов и маркерами меток, клавиши плеера, ресайз/сворачивание панелей.
- **M6. Теги.** Иерархия ≤5 уровней, CRUD, счётчики, таб «Теги», drag&drop на файлы, мультивыбор (объединение/пересечение), фильтр списка, теги файлов/сегментов/меток, `tag:` в поиске, экспорт/импорт.
- **M7. Метки + поиск по меткам.** Руководство: `＋ метка`, drag по таймлайну, `Ctrl+M`, выделение строк таймингов; диалог (start/end/label/color/tags/note); resize-ручки; отображение на таймлайне и в панели; контекстные меню; undo; теги меток; поиск `scope=annotations`, фильтры по тегу/цвету/видео, панель «Метки», переход на таймкод с подсветкой; экспорт/импорт JSON.
- **M8. Упаковка.** Docker `ubuntu:22.04`, PyInstaller onedir, ffmpeg/ffprobe + модель в `extraResources`, electron-builder `.deb`/`.AppImage`, sandbox, проверка на чистой VM, размеры, лицензии.
- **M9. Полировка.** Клавиши и окно «О клавишах», настройки, темы, toast, обработка ошибок, i18n, доступность, восстановление состояния, финальный прогон §7.
- **A. Приёмка и CI.** Матрица §7, скрипты `ci.sh`/`acceptance.sh`, `docs/acceptance.md`, замеры RAM/CPU/диска, offline-проверка, чек-лист релиз-кандидата.

## 7. Как обеспечено требование «ручные метки + поиск по меткам»

| Требование пользователя | Реализация | Критерий проверки |
|---|---|---|
| Вручную поставить метку на видео | Тулбар `＋ метка`, `Ctrl+M` на позиции плеера, диалог с полями (M7) | E2E: создать метку → появилась на таймлайне и в панели |
| Поставить метку на диапазон | Drag по таймлайну с превью; выделение строк таймингов → «Создать метку»/`Ctrl+M`; bulk-API (M7) | E2E: выделить диапазон → `00:30–01:15` сохранена с точностью ±100 мс |
| Управлять метками | Панель «Метки»: список, фильтры (текст/тег/цвет/видео), редактирование в диалоге и inline, удаление, undo, экспорт/импорт JSON (M7) | E2E: правка/удаление/undo; экспорт → импорт без потерь |
| Искать по своим меткам | `GET /api/search?scope=annotations` (FTS label+note), `tag:`-фильтр, фильтр по цвету; панель «Метки» с debounce (M4/M6/M7) | Integration: запрос по слову из метки → `kind:"annotation"` с timecode; клик → seek |
| Найти метку по тегу | `annotation_tags`, фильтр `tag_ids` в `/annotations` и `/search`, `tag:` в строке поиска (M6/M7) | Integration: тег «важное» → возвращаются только метки с тегом |
| Увидеть метку на таймлайне | Цветные маркеры с tooltip, клик → seek, подсветка выбранной (M5 отображение / M7 контролы) | E2E: клик по маркеру → плеер на `start_ms` |
| Управление с клавиатуры | `Ctrl+M`, `Shift+I`/`Shift+O` (in/out), `Delete`, `Esc`, `Ctrl+Z/Y`, `Space`; окно «О клавишах» (M7/M9) | E2E: сценарий только с клавиатуры |

Сквозные сценарии (обязаны быть в `docs/acceptance.md`, `plans/10`):

1. Урок 10 мин → создать метку 00:30–01:15 «важный пример» с тегом «важное» и цветом → видна на таймлайне и в панели.
2. Ввести в поиск слово из названия метки → в результатах строка «метка» с таймкодом → клик → плеер на 00:30, маркер подсвечен.
3. Ввести `tag:важное` → список меток с этим тегом (включая дочерние теги).
4. Перетащить границу метки на таймлайне → сохранено, повторный клик ведёт на новый `start_ms`.
5. Удалить метку → `Ctrl+Z` возвращает её вместе с тегами.
6. Закрыть/открыть приложение → метки, фильтры и ширины панелей восстановлены.

## 11. Процесс работы с планами

1. Перед этапом: прочитать `TARGET.md` §6 (milestone), план этапа и `plans/00-conventions.md`.
2. Работать по задачам `T-<этап>.<номер>` по порядку; каждый коммит — рабочее состояние.
3. Закрывать этап только по DoD (`plans/00` §11) и обновлять статус в таблице §5 этого файла.
4. Новый контракт — только через правку `plans/00-conventions.md` (owner: Lead) + пометка «новое» в плане этапа.
5. Не менять `TARGET.md`; расхождения со спекой фиксируются в §2/§12 и в «Открытых вопросах» планов.
